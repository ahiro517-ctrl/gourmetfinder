# 取材候補ソーシング 仕様書（確定版 v1.0）

## 0. 目的
品川駅・港南エリアの飲食店から「取材したい候補」を、**理由付き**で毎週自動提案する。
人間が簡単なフィードバック（○/△/×）を返すと、次回以降のおすすめ順位に反映される。

## 1. 対象エリア
- 港区港南（品川駅 港南口側）
- 品川区 北品川 1〜2丁目
- 品川区 東品川 1丁目

港区・品川区にまたがるため、行政区ではなく**緯度経度の近似ポリゴン**で内外を判定する
（`config/config.yaml` の `area.polygon`）。Places検索は円形指定なので、エリアを覆う複数の円で
取得 → ポリゴン内のみ採用、という流れ。v1は近似ポリゴンで開始し、後から精密境界に差し替え可能。

## 2. データソース
**Google Places API (New) のみ**。
- `searchNearby`（円内の店舗一覧）でエリア内店舗を取得
- `searchText`（任意・既定オフ）でチェーンの全国件数チェック

取得シグナル: 店名 / 位置 / 業種 / 評価(rating) / 口コミ数 / 価格帯 / 営業ステータス。

### 新店オープンの検知
Places には「開店日」が無いため、**状態差分**で検知する。
- 毎週、エリア内の `place_id` 一覧をスプレッドシートに保存
- **前回まで未出現 かつ 口コミ数が少ない**（既定 ≤15件）place_id を「新店の可能性あり」とする
- 初回実行は基準作成のみ（全件を新店扱いしない）
- 注意: 「初出現＝必ず新店」ではない（登録が遅れた既存店もある）。口コミ数の少なさを併用して確度を担保。

## 3. スコアリング（軽量・重み調整式）
`スコア = Σ ( 重み[k] × 特徴量[k] )`

| 特徴量 | 向き | 内容 |
|---|---|---|
| new_store | + | 新店の可能性（初出現＋口コミ少） |
| rating | + | 一定口コミ数を満たす高評価（3.0→0, 5.0→1 に正規化） |
| hidden_gem | + | 高評価(≥3.8)×口コミ少なめ＝穴場 |
| independent | + | 独立系（チェーンでない） |
| chain_penalty | − | 全国チェーンは減点（除外ではない） |

重みは `config/weights.yaml`。チェーン判定は `config/chains.yaml` のキーワード一致＋（任意で）全国件数チェック。

### 取材理由
寄与した特徴量からテンプレで日本語の理由文を生成（例:「新規オープンの可能性 / 高評価ながら口コミ少なめの穴場 / 独立系で独自性あり」）。
LLM(Claude)による理由文の高品質化は将来オプション。

## 4. フィードバック＆学習（軽量）
出力先・入力先は **Google スプレッドシート**。「候補」タブの列:

`実行日 | place_id | 店名 | 住所 | 業種 | スコア | 取材理由 | 評価 | タグ | コメント | ステータス`

人間は **評価(○/△/×)** ・**タグ**（チェーン嫌 / 遠い / ジャンル違い / 良い 等）・コメント・ステータス(未/取材済)を記入。

学習（パーセプトロン的更新）:
- ○ → その店の特徴量の方向に重みを少し上げる
- × → 下げる
- △ → 変更なし
- × かつ タグに「チェーン」→ その店名をチェーン語に追加

学習後の重みは `config/weights.yaml` / `config/chains.yaml` に保存し、GitHub Actions が自動コミット（変更履歴が残る）。
内部状態（既出 place_id・学習済み place_id）はスプレッドシートの `_state` タブに保存。

## 5. 実行
- **GitHub Actions の週次 cron**（毎週月曜 09:00 JST）。手動実行も可。
- サーバ不要。必要なのは GitHub Secrets 3つ（APIキー / サービスアカウントJSON / スプレッドシートID）。

## 6. 重複防止
一度「候補」タブに出した place_id は再提案しない。×（却下）・取材済は除外リスト扱い。

## 7. 技術構成
- 言語: Python 3.11
- 主要ライブラリ: requests / gspread / google-auth / PyYAML（ポリゴン判定は依存なしの自前実装）
- 構成: `gourmetfinder/`（パッケージ） + `config/`（人が編集する設定） + `.github/workflows/weekly.yml`

スコア順の候補一覧とCSVを出力する。ロジックの確認・調整に使う。
