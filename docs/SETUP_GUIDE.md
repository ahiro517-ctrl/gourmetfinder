# セットアップ手順書（非エンジニア向け・クリックだけで完了）

このツールは「**週1回、品川・港南エリアの取材候補をスプレッドシートに自動で出してくれる**」仕組みです。
一度セットアップすれば、あとは**勝手に動きます**。あなたはスプレッドシートを見て○×を付けるだけ。

専門知識は不要です。下の手順を上から順番に、画面の指示どおりにクリックしていけば完了します。
所要時間は **30〜40分** ほど。途中でわからなくなったら、その項目の番号を伝えてください。

---

## 🗺 全体像（何をするのか）

セットアップでやることは、ざっくり次の3つだけです。

1. **提案を書き込む「スプレッドシート」を1枚用意する**
2. **Googleの「鍵」を2つ発行する**（地図情報を取る鍵＝APIキー / シートに書き込む鍵＝サービスアカウント）
3. **その鍵を GitHub に登録する**（登録するとロボットが毎週動き出します）

```
   あなた                Google               GitHub（自動実行）
  ┌──────┐  鍵を発行   ┌──────────┐  鍵を登録  ┌────────────┐
  │ シート │ ─────────▶│ APIキー   │ ────────▶│ 毎週ロボットが │
  │ 用意   │           │ サービス  │          │ 候補を書き込む │
  └──────┘           │ アカウント │          └────────────┘
       ▲              └──────────┘                  │
       └──────────── 毎週ここに提案が届く ◀────────────┘
                      （あなたは○×を付けるだけ）
```

---

## 🧰 用意するもの

- **Googleアカウント**（GmailがあればOK）
- **GitHubアカウント**（このコードが置いてある場所。すでにあるはずです）
- クレジットカード（Google Cloudの登録に必要。**通常このエリア・週1なら無料枠の範囲内**で、課金される可能性は低いです。詳しくは末尾「料金の目安」参照）

---

## STEP 1. 提案を書き込むスプレッドシートを用意する（5分）

1. ブラウザで [https://sheets.google.com](https://sheets.google.com) を開く
2. 「**空白のスプレッドシート**」をクリックして新規作成
3. 左上のファイル名（「無題のスプレッドシート」）を **「取材候補リスト」** など好きな名前に変更
4. ブラウザのアドレスバーのURLを見ます。次のような形のはずです：
   ```
   https://docs.google.com/spreadsheets/d/【ここが長い英数字＝シートID】/edit#gid=0
   ```
   この **`/d/` と `/edit` の間の長い英数字** が「スプレッドシートID」です。
   コピーしてメモ帳に貼っておいてください（あとで STEP 5 で使います）。

> 💡 表の見出し（列名）は自分で作らなくてOKです。ロボットが初回実行時に自動で作ります。

---

## STEP 2. Google Cloud のプロジェクトを作る（5分）

「プロジェクト」は、鍵を入れておく箱のようなものです。

1. [https://console.cloud.google.com](https://console.cloud.google.com) を開く
2. 初めての場合、利用規約への同意やお支払い情報（クレジットカード）の登録を求められます。画面に従って登録してください。
3. 画面上部の「プロジェクトを選択」→「**新しいプロジェクト**」をクリック
4. プロジェクト名を **「gourmetfinder」** などにして「作成」
5. 作成後、上部のプロジェクト選択が「gourmetfinder」になっていることを確認

---

## STEP 3. 地図情報を使えるようにする（Places APIを有効化）（3分）

1. 上部の検索バーに **「Places API (New)」** と入力して検索
2. 検索結果の「**Places API (New)**」をクリック
3. 「**有効にする**」ボタンをクリック

> もし「Places API (New)」が見つからない場合は「Places API」でもOKですが、できれば「(New)」付きを選んでください。

---

## STEP 4. 鍵その1「APIキー」を発行する（3分）

これは「地図情報を取得するための鍵」です。

1. 左メニュー（≡）→「**APIとサービス**」→「**認証情報**」を開く
2. 上部「**＋ 認証情報を作成**」→「**APIキー**」をクリック
3. 鍵（長い文字列）が表示されます。**コピーしてメモ帳に貼っておく**（STEP 6 で使います）
4. （任意・推奨）「キーを制限」から、使えるAPIを「Places API」に限定しておくと安全です

---

## STEP 5. 鍵その2「サービスアカウント」を発行する（10分）

これは「スプレッドシートに書き込むための鍵」です。少し手順が多いですが、ゆっくりどうぞ。

1. 左メニュー →「**APIとサービス**」→「**認証情報**」
2. 上部「**＋ 認証情報を作成**」→「**サービスアカウント**」をクリック
3. サービスアカウント名を **「gourmetfinder-bot」** などにして「作成して続行」
4. 「ロールを選択」は**そのまま「続行」→「完了」**でOK（権限は後でシート側で付けます）
5. 作成されたサービスアカウントの一覧に、メールのような文字列（例: `gourmetfinder-bot@gourmetfinder-xxxx.iam.gserviceaccount.com`）が表示されます。
   この **メールアドレスをコピーしてメモ**（STEP 5.5 で使います）
6. そのサービスアカウントをクリック →「**キー**」タブ →「**鍵を追加**」→「**新しい鍵を作成**」
7. 形式は「**JSON**」を選んで「作成」。すると **JSONファイルが1つダウンロード**されます。
   このファイルが「鍵その2」です。大切に保管してください（STEP 6 で中身を使います）。

### STEP 5.5. スプレッドシートをこのサービスアカウントに共有する（重要）

ロボットがシートに書き込めるよう、**STEP 1 のシートを、STEP 5 のメールアドレスに共有**します。

1. STEP 1 で作ったスプレッドシートを開く
2. 右上の「**共有**」ボタンをクリック
3. 宛先に **STEP 5-5 でメモしたサービスアカウントのメールアドレス** を貼り付け
4. 権限を「**編集者**」にして「送信」
   （「通知」のチェックは外してOK。相手はロボットなのでメールは届きません）

> ⚠️ ここを忘れると「シートに書き込めません」というエラーになります。必ず実施してください。

---

## STEP 6. 鍵を GitHub に登録する（5分）

発行した鍵を、自動実行する GitHub に登録します。これが終われば準備完了です。

1. ブラウザで、このコードのある GitHub リポジトリ（`ahiro517-ctrl/gourmetfinder`）を開く
2. 上部タブの「**Settings（設定）**」をクリック
3. 左メニューの「**Secrets and variables**」→「**Actions**」をクリック
4. 「**New repository secret**」ボタンで、次の **3つ** を1つずつ登録します。

| Name（名前。完全に一致させる） | Secret（中身） |
|---|---|
| `GOOGLE_PLACES_API_KEY` | STEP 4 でコピーしたAPIキー |
| `GOURMET_SPREADSHEET_ID` | STEP 1 でメモしたスプレッドシートID |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | STEP 5 でダウンロードしたJSONファイルを**テキストエディタで開き、中身を全部コピーして貼り付け**（`{` から `}` まで丸ごと） |

> 💡 JSONの中身は、メモ帳やテキストエディットでファイルを開くと `{ "type": "service_account", ... }` という文字がたくさん入っています。**その全部**を貼り付けてください。

---

## STEP 7. 動かしてみる（3分）

手動で一度実行して、ちゃんと動くか確認します。

1. GitHub リポジトリの上部タブ「**Actions**」をクリック
2. 左の一覧から「**取材候補ソーシング（週次）**」をクリック
3. 右側の「**Run workflow**」ボタン →（ブランチはそのまま）→「**Run workflow**」をクリック
4. 1〜2分待つと処理が走ります。緑のチェック✅が付けば成功です
5. STEP 1 のスプレッドシートを開くと「**候補**」というタブができ、店舗が並んでいるはずです🎉

> ⚠️ **初回は新店判定が行われません**（“いつもの状態”を覚えるための準備回のため）。
> それでも高評価・穴場・独立系の店は提案されます。新店オープンの検知は2回目以降から効きます。

---

## 📝 使い方：フィードバックの付け方

「候補」タブで、提案された各店に対して次の列を埋めるだけです（埋めなくても害はありません）。

| 列 | 何を書く | 例 |
|---|---|---|
| **評価** | 取材したいなら `○` / 微妙なら `△` / 却下なら `×` | `○` |
| **タグ** | 短い理由ラベル（カンマ区切りでも可） | `良い` / `チェーン嫌` / `遠い` / `ジャンル違い` |
| **コメント** | 自由メモ | 「内装が独特で画になりそう」 |
| **ステータス** | 取材が済んだら `取材済` | `取材済` |

ロボットは**次回実行時にこれを読んで学習**します。
- `○` を付けた店の傾向が、次回から上位に出やすくなります
- `×` を付けた店、`取材済` の店は、もう再提案されません
- `×` ＋ タグ「チェーン嫌」を付けると、その店名がチェーン扱いになり今後減点されます

> 💡 学習は「ゆっくり効く」設計です。1回で激変はしません。数週間ぶん○×を付けるほど、あなた好みに寄っていきます。

---

## ⚙️ あとから調整したいとき（任意）

`config/` フォルダの中身を GitHub 上で直接編集できます（編集→Commitで反映）。

- `config/config.yaml` … エリアの範囲・1回の提案件数・対象業種など
- `config/weights.yaml` … 何を重視するか（数字が大きいほど重視）。※学習で自動更新もされます
- `config/chains.yaml` … チェーン扱いする店名キーワード

数字や地名を書き換えるだけです。プログラムを触る必要はありません。

## 💰 料金の目安と「無料の範囲に抑える」設定

### 目安
- **Google Places API**: 本ツールは1回の実行で約3回（検索する円の数だけ）しか呼びません。週1なら**月12回程度**で、Googleの無料枠（月1万回規模）に対して**ごくわずか**。実質ゼロ円です。
- **Google Sheets API**: 無料（課金対象外）。
- **GitHub Actions**: パブリック/個人利用の通常範囲なら無料です。

課金対象は実質 **Places API だけ**です。念のため、絶対に課金させない設定を2つ入れておくと安心です。

### ① 予算アラート（簡単・まず必須）
1. Google Cloud →「**お支払い**」→「**予算とアラート**」→「**予算を作成**」
2. 対象プロジェクトを **gourmetfinder** に
3. 金額を低めに設定（例: **月 ¥500**）
4. しきい値 50% / 90% / 100% でメール通知 →「作成」
   - ※「通知」であって自動停止ではありませんが、この使用量なら鳴ることはまずありません。

### ② 1日の上限を物理的にかける（確実な歯止め）
1. Google Cloud →「**APIとサービス**」→「**Places API (New)**」→「**割り当てとシステム上限（Quotas）**」
2. 「Requests per day（1日あたりのリクエスト数）」を低い値（例: **100**）に編集
   - これを超えると**それ以上は呼べなくなる**ので、万一暴走しても課金を防げます。週12回程度の運用に100/日なら十分です。

### そのほかの節約ポイント
- APIキーは「**Places API (New) のみ**」に制限しておく（他の有料APIに転用されない）。
- `config/config.yaml` の `enable_nationwide_chain_check` は **false（オフ）のまま**にする（オンにすると呼び出しが増えます）。

## 🆘 困ったとき（トラブルシュート）

| 症状 | 原因と対処 |
|---|---|
| Actionsが赤❌になる／「書き込めません」 | STEP 5.5 のシート共有を忘れていないか確認（サービスアカウントのメールに**編集者**で共有） |
| 「APIキーが無効」「PERMISSION_DENIED」 | STEP 3 の Places API 有効化、STEP 6 の `GOOGLE_PLACES_API_KEY` の貼り間違いを確認 |
| シートに何も出ない | STEP 6 の `GOURMET_SPREADSHEET_ID` が正しいか（`/d/` と `/edit` の間の文字列）確認 |
| JSONのエラー | `GOOGLE_SERVICE_ACCOUNT_JSON` に `{`〜`}` の中身が**全部**入っているか確認 |
| 新店が出ない | 初回は判定なし。2回目以降に効きます |

それでも解決しない場合は、Actions の赤❌になった実行を開き、エラーメッセージのある行を伝えてください。

## 🤖 動作確認（パソコンに詳しい人向け・任意）

クラウドに登録する前に手元でロジックを試したい場合：

```bash
pip install -r requirements.txt
python -m gourmetfinder --dry-run
```

サンプルデータでスコア順の候補一覧が表示され、`fixtures/dry_run_output.csv` が出力されます（APIキー不要）。
